한반도 객관기후예측 · 매일 운영 흐름

서버 없이 GitHub 안에서만 돕니다. GitHub Actions 러너가 정해진 시각에 Open-Meteo에서 예측을 받아 계산하고, 결과를 gh-pages 브랜치에 올리면 GitHub Pages가 웹으로 내보냅니다. 평년 자료는 미리 한 번 받아 저장소에 넣어 두고 매일 읽기만 합니다.

자료원 (외부 API) 실행 (GitHub Actions) 저장 (GitHub 저장소) 표출 (웹)

1. 매일 전망 산출과 게시

예약 시각, 코드 변경(push), 수동 실행 중 하나로 시작합니다. 계산부터 게시까지 2~3분 걸립니다.

2. 평년 자료 준비 (한 번 받아 저장소에 보관)

관측·재분석 평년과 격자 고도는 바뀌지 않으므로 처음 한 번만 받아 기본 브랜치에 커밋했습니다. 매일 산출은 이 파일을 읽기만 해서 기상청 인증키 없이도 돕니다.

3. 하루 시간표 (한국 시간)

EC46 새 자료가 공개된 뒤 정기 실행이 돕니다. GitHub 예약 실행은 늦거나 빠질 수 있어 세 번 걸어 두었고, 그날 07시 이후 발표가 이미 있으면 뒤의 실행은 건너뜁니다.

실행을 시작하는 세 가지 방법

  • 예약: 매일 07:10 · 08:40 · 12:10 KST (cron, UTC로 22:10 · 23:40 · 03:10)
  • 코드 변경: pipeline/, site/, 워크플로 파일을 push 하면 즉시
  • 수동: 저장소 Actions → 「객관기후예측 갱신」 → Run workflow

멈추거나 실패했을 때

  • 마지막 발표가 30시간을 넘기면 지도 상단에 '갱신 지연'이 뜹니다.
  • 07:10이 지났는데 그날 발표가 없으면 '반영 대기' 안내가 뜹니다.
  • Actions 화면에서 실행 기록과 로그를 봅니다. 60일 동안 커밋이 없으면 GitHub가 예약을 멈춥니다.
